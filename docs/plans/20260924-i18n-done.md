# i18n integration (en + de)

## Context

The frontend has every user-visible string hardcoded in English (templates, `aria-label`s, TS-side
strings, `THEME_LABELS`, one `confirm()`), no locale-aware routing, and `DecimalPipe` formatting fixed
to `en-US`. The shared house rules (`claude-config/frontend-angular.md`) already define the target
shape: `TranslationService.t('key')`, keys in **both** `en.json` and `de.json`, locale-prefixed routes
`/:locale/...` (`en`, `de`), `LocaleService.currentLocaleFromUrl()`, nav links carrying the locale
segment. This plan implements exactly that; no new library (no `@angular/localize`/transloco) is added.

Findings that shape the design: no `LocaleService`/`TranslationService`/i18n files exist; routes are flat
(`app.routes.ts`); 4 `routerLink`s in `header.component.html`; the backend sends no localized text and
the frontend never displays backend error bodies (no backend change); the Express SPA fallback already
serves `/de/accounts` deep links; DB data (category/account/payee names) is user data, not translated.

## Design decisions

- **Dictionaries as typed TS-imported JSON**, not HTTP-fetched assets: `packages/frontend/src/i18n/en.json`
  and `de.json` (deviates from the template's `assets/i18n` path, which would need an `assets` entry and
  async loading; the dictionaries are tiny). `resolveJsonModule` on.
  - `TranslationKey = keyof typeof en` — `de` is typed `Record<TranslationKey, string>`, so a key missing
    in either language is a **compile error** (SPOT, no runtime fallback, no silent defaults).
- **`TranslationService`** (`core/services/translation.service.ts`, root): `t(key, params?)` reads the
  `LocaleService.locale` signal, so templates stay reactive under OnPush. Params via `{name}`
  placeholders (needed for pagination: `Page {page} of {totalPages} ({total} total)`); a missing param
  throws.
- **`LocaleService`** (`core/services/locale.service.ts`, root): `locale` signal (`'en' | 'de'`),
  `currentLocaleFromUrl()`, `setLocale(locale)`, `detectPreferred()` (`navigator.language` starts with
  `de` → `de`, else `en`). Locale type/`SUPPORTED_LOCALES` in `core/models/locale.model.ts` (mirrors
  `theme.model.ts`). Sets `document.documentElement.lang` in an `effect`. Initial value parsed from
  `location.pathname`, updated on router `NavigationEnd`. No localStorage persistence (URL is the source
  of truth; bare URLs fall back to browser language) — KISS.
- **Routing**: `app.routes.ts` becomes `{ path: ':locale', canMatch: [supportedLocaleGuard], children:
  [accounts, transactions, categories, payees, '' → accounts] }`; `''` and `'**'` redirect (function
  `redirectTo`) to `/{detectPreferred()}/accounts`. Guard `core/guards/supported-locale.guard.ts`.
- **Header links**: `[routerLink]="[locale.locale(), 'accounts']"`-style absolute links including the
  locale; `routerLinkActive` keeps working.
- **Language switcher** in the user menu (per `frontend.md`: preferences belong there, not in nav): a
  "Language" row + radio submenu mirroring the existing "Theme" one (same CSS classes, same
  `cdkMenuItemRadio` pattern). Selecting swaps the first URL segment via `Router.navigateByUrl`,
  preserving query params/fragment. Language names are endonyms ("English", "Deutsch") — not translated.
  Any new user-menu SCSS stays structural-only; visuals via existing tokens/theme files.
- **Formatting**: `registerLocaleData(localeDe)` in `app.config.ts`; pass the locale explicitly to the two
  `DecimalPipe` sites (`accounts`, `transactions` templates: `| number:'1.2-2':locale.locale()`), because
  `LOCALE_ID` is fixed at bootstrap and can't follow URL switches. Dates stay `yyyy-MM-dd` (neutral).
- **TS-side strings** become computed/`t()` calls: `THEME_LABELS` → keys `theme.<name>` (theme.model keeps
  names; labels via `t`), `user-menu` `ariaLabel`, `dark-mode-toggle` `label`, `categories.component.ts`
  `saveError` + `confirm(...)`.
- **Race check**: locale changes only via navigation; `locale` signal derives from `NavigationEnd`, so
  in-flight navigations can't leave URL and signal out of sync for longer than one navigation. Switch
  handler reads `router.url` at click time and navigates (last click wins).
